## [v0.4.1] - 2026-11-25

### Highlights

- A step whose checks fail stops the run: run exits non-zero, and a phase run stops there instead of reporting the phase done

### Fixed

- A step whose actions were done but whose checks failed was recorded as failed while run returned success, so a phase run went on and reported the phase done; Run now returns ErrChecksFailed, and the phase run says which checks failed, how to check again and how to resume ([`988314d`](https://github.com/plexusone/systemspec-runbook/commit/988314d))

### Documentation

- The getting-started guide says what a run does when a step's checks fail

## [v0.4.0] - 2026-11-25

### Highlights

- Set everything up once, then run a whole phase: prepare lists every variable and input a run needs, run <phase> checks them all before its first step, and a failure says where it stopped and how to fix it

### Added

- `run <phase>` runs a phase's steps in order, skipping those already done or verified, stops at the first that fails, is stopped, or waits outside the phase, and resumes there; `Runner.RunPhase` ([`e9b1309`](https://github.com/plexusone/systemspec-runbook/commit/e9b1309))
- A failed run's report: the phase, step, action and command, its error and the last lines of its output, the matching fixes, and the commands that resume the phase or retry the step; `Failure` ([`e9b1309`](https://github.com/plexusone/systemspec-runbook/commit/e9b1309))
- `Troubleshoot` on a runbook and a step: fixes whose pattern, a Go regular expression, matches a failure's output; listed on both pages ([`1aa5bcd`](https://github.com/plexusone/systemspec-runbook/commit/1aa5bcd))
- `Inputs`: values in the environment, marked `secret` when never to be shown, and preconditions a command checks, each with how to set it up; a step's `needs` names those it needs, and a run checks them before it starts ([`8dcaf61`](https://github.com/plexusone/systemspec-runbook/commit/8dcaf61))
- `prepare <step|phase|all>` lists every variable and input a run needs, which are set, missing, derived or produced later, and how to set up each one missing, without showing a value; `Runner.Requirements`, `Runbook.Remaining` ([`7985713`](https://github.com/plexusone/systemspec-runbook/commit/7985713))
- `--env-file` on `run` and `prepare` loads `NAME=value` lines, expanding `$NAME` as a shell does, without replacing the environment; `prepare --write-env` writes such a file with no values; `LoadEnvFile`, `EnvTemplate` ([`7985713`](https://github.com/plexusone/systemspec-runbook/commit/7985713))
- Before You Start on both pages: every variable and input with how to set it up and the steps that use it; each step links the inputs it needs ([`8dcaf61`](https://github.com/plexusone/systemspec-runbook/commit/8dcaf61))
- `Runbook.Phase` and `Runbook.PhaseOf` ([`1aa5bcd`](https://github.com/plexusone/systemspec-runbook/commit/1aa5bcd))

### Changed

- A failed `run` no longer prints the command's usage after its report ([`6832b6a`](https://github.com/plexusone/systemspec-runbook/commit/6832b6a))
- The runbook's JSON Schema adds `inputs`, `troubleshoot` and a step's `needs` and `troubleshoot` ([`8dcaf61`](https://github.com/plexusone/systemspec-runbook/commit/8dcaf61))

### Documentation

- The README and Getting Started describe inputs, prepare, phase runs and troubleshooting ([`645127d`](https://github.com/plexusone/systemspec-runbook/commit/645127d))

## [v0.3.0] - 2026-11-25

### Highlights

- Recurring runbooks, such as a deploy, are run again from their first step, and a runbook's state says when each run began, finished or failed

### Added

- `Runbook.Recurring` marks a runbook that is run again; `Log.Restart` begins a new run, `Log.Runs` records when each began, and a step's state comes from the current run's events while earlier runs stay as history ([`592b503`](https://github.com/plexusone/systemspec-runbook/commit/592b503))
- `StateOf` returns a `RunbookState`: each run's start, who began it and why, its last event, when it finished, its outcome (`not-started`, `in-progress`, `failed` or `finished`) and its steps by state, and when the runbook last finished ([`592b503`](https://github.com/plexusone/systemspec-runbook/commit/592b503))
- `Log.NextRunStart` and `Log.Current`: the earliest time a new run can begin, and the current run's events ([`592b503`](https://github.com/plexusone/systemspec-runbook/commit/592b503))
- `restart` and `state` commands; `state` prints text or `--format json` ([`122e8bb`](https://github.com/plexusone/systemspec-runbook/commit/122e8bb))
- On the HTML page, every link to another page is followed by an icon that opens it in a new tab; links within the page get none, and the icon needs no script ([`14ff93f`](https://github.com/plexusone/systemspec-runbook/commit/14ff93f))

### Changed

- The event log's schema adds `runs`, and the runbook's schema adds `recurring`; a log without runs is one run, so existing logs read as before ([`592b503`](https://github.com/plexusone/systemspec-runbook/commit/592b503))

## [v0.2.0] - 2026-11-22

### Highlights

- HTML pages are built from the runbook with templ components: full width, each step a section with its owner's badge, a copy button on every command, anchors shared with the Markdown page

### Added

- A copy button on every code block of the HTML page, for pasting a command into a terminal; `Script` is the script, for hosts that place the fragment in their own page ([`cb541bf`](https://github.com/plexusone/systemspec-runbook/commit/cb541bf))

### Changed

- `Runbook.HTML` renders the runbook directly with templ components instead of converting its Markdown page: a full-width page, the phase summary as a table, each step a section with owner badges, its dependencies linked, its actions numbered with their commands escaped, and its credentials, done sentence and checks. Text fields are still Markdown, converted without raw HTML ([`4ee4dc8`](https://github.com/plexusone/systemspec-runbook/commit/4ee4dc8))
- `Style` uses the window's full width and adds step and badge styles ([`4ee4dc8`](https://github.com/plexusone/systemspec-runbook/commit/4ee4dc8))

### Dependencies

- _1 dependency update_

## [v0.1.0] - 2026-11-22

### Highlights

- A runbook as data: phases of steps with owners, dependencies, actions and typed checks, validated, rendered as Markdown or HTML, recorded in an event log, and run step by step

### Added

- The runbook model: phases, steps with an owner (operator, agent or both), dependencies, actions, a done sentence, checks and the credentials a step creates, with validation reporting every problem ([`d0dca40`](https://github.com/plexusone/systemspec-runbook/commit/d0dca40))
- An event log and each step's derived state: blocked, ready, in-progress, done or verified ([`2bdd4a4`](https://github.com/plexusone/systemspec-runbook/commit/2bdd4a4))
- Typed checks: dns, http, unreachable, command, and named checks a host registers in Go; checks only read, and report pass, fail or skip ([`0086b59`](https://github.com/plexusone/systemspec-runbook/commit/0086b59))
- Variables: declared {{name}} references in text, commands and checks, filled from flags, providers, the environment, or a command the variable declares ([`1f30a1e`](https://github.com/plexusone/systemspec-runbook/commit/1f30a1e))
- Guided runs: show each action with its variables filled, confirm and run commands without a shell, wait on a person's steps, stop at the first failure, record the step and run its checks; a new secret is generated in Go and piped to the program that stores it ([`d2ef546`](https://github.com/plexusone/systemspec-runbook/commit/d2ef546))
- A Markdown page with step and key links that never need anchors typed by hand, and a check for broken relative links ([`be49ba2`](https://github.com/plexusone/systemspec-runbook/commit/be49ba2))
- An HTML page: the Markdown page styled for light and dark themes, or its body for a host's own page, with raw HTML never passed through and angle-bracket placeholders shown ([`f2197d2`](https://github.com/plexusone/systemspec-runbook/commit/f2197d2))
- The Cobra commands a host tool mounts (validate, list, show, record, verify, run, doc with --html, schema), with a renameable events flag, and runbookspec, the command line over a runbook kept as JSON ([`4fe55c5`](https://github.com/plexusone/systemspec-runbook/commit/4fe55c5))
- JSON Schemas of a runbook and its event log, generated and embedded ([`5cc179a`](https://github.com/plexusone/systemspec-runbook/commit/5cc179a))
