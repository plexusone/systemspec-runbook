# Release Notes v0.1.0

Released: 2026-11-22

## Highlights

The first release. A runbook is data: phases of steps, each with an
owner, its dependencies, the actions that do it, the sentence that says
when it is done, and typed checks that prove it. A program declares it
from its own facts; systemspec-runbook validates it, renders it, records
what was done, derives where each step stands, and runs it step by step.

## Added

- **The model.** Phases and steps with an owner (`operator`, `agent` or
  `both`), dependencies, actions, a done sentence, checks, and the
  credentials a step creates. Validation reports every problem at once.
- **State from an event log.** Each step is `blocked`, `ready`,
  `in-progress`, `done` or `verified`, derived from its dependencies and
  the log.
- **Typed checks.** `dns`, `http`, `unreachable`, `command`, and named
  checks a host registers in Go. Checks only read, and report `pass`,
  `fail` with what they saw, or `skip` with why.
- **Variables.** `{{name}}` in text, commands and checks, filled from
  flags, a host's providers, the environment, or a command the variable
  declares.
- **Guided runs.** `run <step>` shows each action with its variables
  filled, asks before each command and runs it without a shell, waits
  for a person's steps, stops at the first failure, records the step and
  runs its checks. A new secret is generated in Go and piped straight to
  the program that stores it.
- **Pages.** Markdown, with links to steps and resolved targets so no
  anchor is typed by hand, and a check for broken relative links. HTML,
  as a page styled for light and dark themes or as its body for a host's
  page; raw HTML in a runbook's text is never passed through, and
  placeholders such as `<value>` are shown.
- **Commands.** The Cobra commands a host tool mounts (`validate`,
  `list`, `show`, `record`, `verify`, `run`, `doc`, `schema`), with an
  events flag a host can rename, and `runbookspec`, the same commands
  over a runbook kept as JSON.
- **Schemas.** JSON Schemas of a runbook and its event log, generated
  from the Go types and embedded.

## Upgrading

A module that required a pseudo-version of systemspec-runbook can
require v0.1.0 instead; nothing else changes.
